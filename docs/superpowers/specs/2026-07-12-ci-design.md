# ClaudeGate CI — Design

**Date:** 2026-07-12
**Status:** Approved, ready for implementation plan

## Problem

ClaudeGate ships to 5k+ marketplace users, but the existing `.github/workflows/ci.yml`
is minimal: it runs `typecheck` + `compile` + `test` on a single OS (Ubuntu / Node 20 /
Python 3.11) and **never runs `lint`**. Two production risks are unguarded:

1. **Cross-platform regressions.** `hook.py` and `SessionManager` compute a workspace
   hash as `MD5(resolvedPath)` that is lowercased on Windows; the hook also shells out
   differently per platform. None of this is exercised on macOS or Windows in CI.
2. **Packaging breakage.** A bad `.vscodeignore` or broken esbuild bundle would only
   surface at publish time — after it is already too late for a released version.

## Goal

Every pull request and every push to `main` must pass lint, typecheck, the full TS +
Python test suite on all three OSes, and a packaging smoke test, before the change can
reach users. **Publishing stays manual** and human-gated via the `release` skill; CI
never publishes.

## Design

Replace the single-job `ci.yml` with two jobs.

### Triggers

```yaml
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:
```

Keeps the current push/PR triggers and adds `workflow_dispatch` for manual runs.

### Job 1 — `test` (OS matrix)

```
strategy:
  fail-fast: false
  matrix:
    os: [ubuntu-latest, macos-latest, windows-latest]
runs-on: ${{ matrix.os }}
steps:
  - actions/checkout@v4
  - actions/setup-node@v4 with node-version 20, cache: npm
  - actions/setup-python@v5 with python-version 3.11
  - npm ci
  - npm run lint
  - npm run typecheck
  - npm run compile
  - npm test
```

- **Adds the missing `lint` step** (defined in `package.json` but absent from CI today).
- Runs on ubuntu + macos + windows so Windows path-hashing / lowercasing and per-platform
  shell behavior in `hook.py` and `sessionManager` are actually exercised.
- `fail-fast: false` so a Windows-only failure does not mask a macOS-only one.
- `cache: npm` on setup-node speeds up `npm ci`.
- `npm test` runs both `test:unit` (esbuild-bundled TS asserts) and `test:hook`
  (`python3 -m unittest discover -s hooks/tests`). Python 3.11 is required for the hook
  tests on every OS in the matrix.

### Job 2 — `package` (Linux only, gated on tests)

```
needs: test
runs-on: ubuntu-latest
steps:
  - actions/checkout@v4
  - actions/setup-node@v4 with node-version 20, cache: npm
  - npm ci
  - npx --yes @vscode/vsce package --no-dependencies -o claudegate.vsix
  - actions/upload-artifact@v4 with the produced claudegate.vsix
```

- `needs: test` — packaging runs only after all three matrix legs pass.
- `vsce package` triggers `vscode:prepublish` → `npm run bundle` automatically, so this
  validates the real production bundle and the `.vscodeignore` contents.
- `--no-dependencies` because the extension bundles everything with esbuild; there is no
  runtime `node_modules` to include.
- The `.vsix` is uploaded as a workflow artifact so any run can be downloaded and
  sideload-tested. Packaging output is OS-independent, so running it once on Linux is
  sufficient.
- `vsce` is intentionally invoked via `npx --yes` rather than added to `devDependencies`,
  matching the existing project convention of installing `vsce` on demand.

## Out of scope (YAGNI)

- **No auto-publish.** `CLAUDE.md` requires releases to be human-gated through the
  `release` skill; CI stops at producing the artifact and never runs `vsce publish` /
  `ovsx publish`.
- **No branch protection changes in this task.** Enabling "require status checks to pass
  before merge" for `main` is a GitHub repo setting, not a file. Documented as a manual
  follow-up: Settings → Branches → add rule for `main` → require the `test` and `package`
  checks.
- **No Node 18 leg, no coverage upload, no version/CHANGELOG consistency checks.** The
  `release` skill already owns version/CHANGELOG/tag consistency; the tests are pure logic
  so one Node runtime per OS is enough.

## Success criteria

- Pushing a branch with a lint error, a type error, a failing TS test, or a failing
  Python hook test causes CI to fail on the relevant OS.
- A change that breaks `.vscodeignore` or the esbuild bundle fails the `package` job.
- A green run produces a downloadable `claudegate.vsix` artifact.
- `package` never starts unless all three `test` legs are green.
- CI never publishes to any registry.

## Files touched

- `.github/workflows/ci.yml` — rewritten (single job → `test` matrix + `package` job).

No source, test, or `package.json` changes are required; all referenced npm scripts
(`lint`, `typecheck`, `compile`, `test`) already exist.
